# Outside tools

The versions and facts each integration is built on. Check the official docs again before changing one.

| Tool | Version | Source | Facts relied on |
|---|---|---|---|
| Claude Code | 2.1.318 | code.claude.com/docs/en/hooks | `PermissionRequest` fires only when Claude Code would ask. Printing nothing leaves its normal prompt in place. A hook timeout doesn't block unless `onFailure: "block"` is set, which Mabari never sets. `additionalContext` carries text to Claude and should read as plain facts. Command hooks run in exec form when `args` is set, with no shell. Hook input carries `session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`; `PermissionRequest` answers with `hookSpecificOutput.decision.behavior` `allow` or `deny`; `Stop` keeps going with `{"decision":"block","reason":…}`; `continue: false` stops Claude. Exit codes other than 2 never block. |
| Codex app server | Docs as of 2026-11-04; CLI not installed here, so tested only against a fake server built from the docs | learn.chatgpt.com/docs/app-server | `codex app-server` over stdio, JSONL, JSON-RPC 2.0 without the `jsonrpc` field. `initialize` with `clientInfo`, then `initialized`. `account/read` gives `{account: {type, email}}`; `account/login/start {type: "chatgpt"}` gives `loginId` and `authUrl`, then `account/login/completed {success}`. `model/list` gives `data[].id`. `thread/start {model, cwd, approvalPolicy, sandbox}` gives `thread.id`; `turn/start {threadId, input: [{type: "text"}]}` gives `turn.id`; `turn/steer` needs `expectedTurnId`; `turn/interrupt {threadId, turnId}`. Items: `commandExecution`, `fileChange` (changes with `path` and `diff`), `agentMessage`, `reasoning`, `webSearch`, `mcpToolCall`. Approvals `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` take `accept`, `acceptForSession`, `decline` or `cancel`. `turn/completed` status is `completed`, `interrupted` or `failed`. `account/logout` is assumed, not confirmed in the docs read. |
| Web Speech API | Browser | developer.mozilla.org, `SpeechRecognition.processLocally` | Marked experimental. When `true`, recognition must be done locally. MDN doesn't state how it fails, so any error stops listening. |
| Web Audio API | Browser | Standard | An `AudioContext` needs a user gesture before it plays. |
| go-keyring | v0.2.8 | github.com/zalando/go-keyring | macOS Keychain, Linux Secret Service, Windows Credential Manager. `MockInit` replaces it in tests. |
| x/crypto | v0.58.0 | pkg.go.dev/golang.org/x/crypto/chacha20poly1305 | `NewX` gives XChaCha20-Poly1305 with a 24 byte random nonce, safe to pick at random each write. |
