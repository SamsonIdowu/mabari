# Outside tools

The versions and facts each integration is built on. Check the official docs again before changing one.

| Tool | Version | Source | Facts relied on |
|---|---|---|---|
| Claude Code | 2.1.318 | code.claude.com/docs/en/hooks | `PermissionRequest` fires only when Claude Code would ask. Printing nothing leaves its normal prompt in place. A hook timeout doesn't block unless `onFailure: "block"` is set, which Mabari never sets. `additionalContext` carries text to Claude and should read as plain facts. Command hooks run in exec form when `args` is set, with no shell. Hook input carries `session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`; `PermissionRequest` answers with `hookSpecificOutput.decision.behavior` `allow` or `deny`; `Stop` keeps going with `{"decision":"block","reason":…}`; `Stop` and `SubagentStop` carry `last_assistant_message`, the final text of the turn, which the docs recommend over reading `transcript_path` because the transcript may lag (checked 2026-11-04); `continue: false` stops Claude. Exit codes other than 2 never block. `MessageDisplay` (command hooks, no matcher) runs as each assistant message streams, in batches with `message_id`, `index`, `final` and `delta`; Claude Code holds each batch until the hook returns, so Mabari's has a 2 second timeout and prints nothing, which leaves the display unchanged (checked 2026-11-04). Common input fields `agent_id` and `agent_type`: `agent_id` is set only inside a subagent; `agent_type` is the agent's name (`general-purpose`, `Explore`, `Plan` or a custom agent's name) inside a subagent, and the `--agent` value for a session started with one, a subagent's type taking precedence. Mabari links a name to a loaded Claude agent file and calls everything else a workflow sub-agent. Hook input has no field saying whether a session runs in a terminal, an editor, on the web or in the Claude app (checked 2026-11-05). |
| Codex app server | Docs as of 2026-11-04; CLI not installed here, so tested only against a fake server built from the docs | learn.chatgpt.com/docs/app-server | `codex app-server` over stdio, JSONL, JSON-RPC 2.0 without the `jsonrpc` field. `initialize` with `clientInfo`, then `initialized`. `account/read` gives `{account: {type, email}}`; `account/login/start {type: "chatgpt"}` gives `loginId` and `authUrl`, then `account/login/completed {success}`. `model/list` gives `data[].id`. `thread/start {model, cwd, approvalPolicy, sandbox}` gives `thread.id`; `turn/start {threadId, input: [{type: "text"}]}` gives `turn.id`; `turn/steer` needs `expectedTurnId`; `turn/interrupt {threadId, turnId}`. Items: `commandExecution`, `fileChange` (changes with `path` and `diff`), `agentMessage`, `reasoning`, `webSearch`, `mcpToolCall`. Approvals `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` take `accept`, `acceptForSession`, `decline` or `cancel`. `turn/completed` status is `completed`, `interrupted` or `failed`. `account/logout` is assumed, not confirmed in the docs read. |
| whisper.cpp | Docs as of 2026-11-04 (`examples/cli/README.md`); not installed here, so tested with a fake `whisper-cli` | github.com/ggml-org/whisper.cpp, huggingface.co/ggerganov/whisper.cpp | The tool is `whisper-cli` (Homebrew `whisper-cpp`). Flags used: `-m` model, `-f` input, `-l` language (`auto` detects), `-t` threads, `-nt` no timestamps, `-np` prints only the result. Mabari sends 16 kHz mono 16 bit WAV. Silence prints `[BLANK_AUDIO]`. Model `ggml-medium.bin`, 1,533,763,059 bytes, SHA-256 `6c14d5adee5f86394037b4e4e8b59f1673b6cee10e3cf0b11bbdbee79c156208` from the Hugging Face API. |
| launchd | macOS 27 | `man launchctl`, `man launchd.plist` | `launchctl bootstrap gui/<uid> <plist>` loads an agent from any path; `bootout gui/<uid>/<label>` unloads it; `kickstart -k` restarts; `kill SIGTERM` stops; `print` shows `state = running`. `RunAtLoad` starts at login from `~/Library/LaunchAgents`, and `KeepAlive` with `SuccessfulExit` false restarts only after a crash. Tested for real by `TestRealService`. |
| systemd user units | systemd 255 docs | `man systemd.unit`, `man systemctl` | `systemctl --user enable --now`, `disable --now`, `daemon-reload`, `is-active`, `try-restart`; `--user -M user@` reaches another user's manager from root; `%h` is the home folder and `%%` a literal percent; units load from `~/.config/systemd/user` and `/usr/lib/systemd/user`. Real install runs in CI only. |
| Task Scheduler | Windows 11 docs | learn.microsoft.com, `schtasks` and the Task XML schema 1.2 | `schtasks /Create /TN <name> /XML <file> /F`, `/Run`, `/End`, `/Delete /F`, `/Query /FO LIST`. The XML file is UTF-16 with a byte order mark. `LogonTrigger`, `InteractiveToken`, `LeastPrivilege` and `RestartOnFailure` (at least a minute apart). Real install runs in CI only. |
| GoReleaser | 2.20.0 | goreleaser.com | `version: 2`; `homebrew_casks` (since 2.10) replaces formulas, and its `hooks.post.install_steps` replaces `install`; `scoops`, `nfpms`, `sboms` (needs syft), `signs` with cosign. Snapshot versions must start with a digit for .deb and .rpm. |
| Claude Code CLI (opening a session) | 2.1.318 | `claude --help` | `claude [prompt]` starts an interactive session with a first prompt; `--name` sets its display name; `--permission-mode plan` starts in plan mode. Mabari opens it in a new Terminal window on macOS (`osascript`, Terminal's `do script`) and in gnome-terminal, konsole or x-terminal-emulator on Linux, with every part shell quoted. `MABARI_NO_TERMINAL=1` turns this off (checked 2026-11-05). A slash command such as `/ux-audit <url>` is sent as the first prompt of a new session, which Claude Code reads as typed input; hook output (`additionalContext`, a Stop `reason`) only reaches the model as context, so a command queued for a running session is reworded as "run the /x command … use the Skill tool". That a first prompt runs a slash command is expected from the CLI reference (`claude "query"` starts an interactive session with that prompt) but has not yet been tried against a real session. |

| Codex custom agents | Codex docs, checked 2026-11-05 | learn.chatgpt.com/docs/agent-configuration/subagents | One TOML file per agent in `~/.codex/agents` (or `$CODEX_HOME/agents`) and `<project>/.codex/agents`. Required: `name`, `description`, `developer_instructions`; optional `model` and other settings, which Mabari keeps when it edits a file. No tools list: an agent inherits the session's permissions and MCP servers. |
