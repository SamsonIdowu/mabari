# Mabari 0.1.0

The first release. Mabari shows your AI agents at work as pixel characters in a little office, on your own computer.

## What's in it

- **The office.** A 2.5D floor with 16 desks, agents that walk in, sit with their lead and talk to each other with flying envelopes. Focus a team, zoom, or go full screen.
- **Agent panel.** Live feed, decision trail built from real events, time estimates from the server, files changed, and Interrupt, Stop and Retry.
- **Instruct and query.** Type or speak. Queries are answered from the log without interrupting the agent; instructions are queued for Claude Code's next checkpoint or sent straight into Codex. Auto dispatch picks the agent for you.
- **Approvals.** Risky actions wait for a click on the floor or the notice board. Auto approve covers low risk actions, or everything if you choose, and says so.
- **Home with Vee.** Ask Vee about your office, by text or by holding the mic.
- **Projects.** Describe a project, attach a folder or a Git repository, and Mabari plans a team. Nothing starts until you approve the plan.
- **Connections.** Claude Code through hooks (shown and backed up before they're written), Codex through `codex app-server` with ChatGPT sign in, Anthropic and OpenAI keys for answering queries, and a hub API for your own agents.
- **Voice.** Push to talk with on-device browser speech or Local Whisper. Nothing is sent without Send or Enter, and voice never approves.
- **Run it your way.** A single binary, a service that starts at login on macOS, Linux and Windows, or Docker with a small hardened image and an optional image with the Claude Code and Codex CLIs inside.
- **Access key.** LAN access, Docker and shared computers ask for an access key. Mabari otherwise answers only on this computer.

## Measured

On an Apple M-series laptop, with the release build and 16 agents reporting through the hub (`go run ./scripts/loadtest`):

| | |
|---|---|
| 10,000 events | 1.06 s, about 9,500 a second, none failed |
| Event latency | p50 1.6 ms, p99 2.5 ms |
| Live updates | about 30,000 delivered to an open page without falling behind |
| Snapshot | 1.7 ms, 87 KB |
| Server memory | 20 MB idle at start, 38 MB after the load |
| Server CPU | 0% idle, 10 seconds after the load |
| Floor frame rate | about 36 fps in headless Chromium while 2,000 events arrive (`web/e2e/perf.spec.ts`). Not yet measured in a normal browser window |

A page that stops reading its live feed is dropped instead of slowing the office, and resumes from where it left off.

## Known limits

- Real Claude Code and Codex sessions, a real microphone and a real whisper.cpp model have been tested by hand only where noted in the project's plan.
- The Linux and Windows services are installed for real only in CI.
- The planner uses fixed rules, not a model, to suggest a team.
- With LAN access on, traffic is plain HTTP. Use it on networks you trust.
